# 关卡格式与规则说明

关卡写在 `src/game/levels.ts` 里，每层是一个 `LevelDef`。规则全部在 `src/game/engine.ts`（纯函数、结果确定），界面、测试、求解器用的是同一份代码。

## 字段

| 字段 | 含义 |
|---|---|
| `id` | 存档键。**上线后不要改、不要重排**，否则玩家的过关记录会对不上 |
| `chapter` | 0 上弦 / 1 齿合 / 2 擒纵 |
| `name` | 层名，显示在钟面和标题栏 |
| `map` | 字符地图，见下表。宽度不超过 11 列（手机竖屏的舒适格子大小），最外一圈应当是墙或空白 |
| `ticks` | 每轮的拍数（发条能走几步） |
| `loops` | 最多能上几次弦（含现在的你） |
| `par` | 参考解用的人数；用这么多人过关得金齿轮 |
| `intro` | 进入时的一句话说明 |
| `tip` | 玩家点「提示」时看到的话 |
| `solution` | 参考解，每轮一个字符串：`U R D L` 走，`W` 等一拍，`|` 收束本轮（剩下的时间原地等） |

## 地图字符

| 字符 | 含义 |
|---|---|
| `#` | 墙 |
| 空格 | 塔外的空白，不画 |
| `.` | 地板 |
| `S` | 出生点（每一轮所有的你都从这里出发） |
| `E` | 钟面（出口） |
| `a`–`d` | 圆盘，颜色 0–3（红、蓝、绿、紫，各配一个形状：圆、三角、方、菱形） |
| `A`–`D` | 门，同色圆盘被压住时打开 |
| `1`–`4` | 反向门，平时开着，同色圆盘被压住时关上（`1` 对应 `a`） |
| `o` | 木箱 |
| `^ > v <` | 巡逻机及其初始朝向 |

## 一拍里发生什么（顺序很重要）

1. **所有的你按顺序行动**，最早的回响先动，现在的你最后动。每个人执行这一拍按下的键：
   - 撞墙、撞到关着的门、推不动的箱子：原地不动，但这一拍照样记录了这个键。
   - 推箱子：箱子前方必须是空地板，不能有墙、关着的门、别的箱子、活着的你或者巡逻机。
   - 你们彼此可以重叠，互相不挡路。
   - 门在一拍之内状态不变，所以「门开着的那一拍你走进去」就一定进得去。
2. **巡逻机移动**：前方是墙、关着的门或箱子就掉头，掉头后仍然被挡住就原地不动。巡逻机不压圆盘。
3. **抓人**：巡逻机和某个你落在同一格，或者两者互换了位置，就抓住编号最小的那个。被抓的你消失，巡逻机停在原地，从此不再移动，也不再挡任何东西。
4. **圆盘和门**：根据活着的你和箱子的位置重新判定。门想关上时，如果门里站着人、放着箱子或者有巡逻机，就关不上（卡门）。
5. **过关**：任何一个活着的你站在钟面上，就过关。

一轮的发条走完（或者现在的你被抓住、按了收束），剩下的拍数会自动按「等」走完，然后时间倒流，下一轮开始。过去的每一个你重演的是**按键**，所以只要世界变了，它就可能走出和当初不同的路线（界面上会变成粉色）。

## 新增或修改关卡

1. 在 `levels.ts` 里写好地图，先把 `solution` 留空。
2. 用求解器找最短解，并确认人数更少时无解：

   ```bash
   npm run solve -- <id>        # 按 par 人数求解
   npm run solve -- <id> 3      # 最多试到 3 个人
   ```

   求解器在所有的你按键的组合上做广度优先搜索。它的模型比真实玩法宽松：它允许较早的你在自己那一轮被抓之后继续行动。所以「无解」的结论是可靠的，「找到解」还需要回放确认。

3. 把解法写进 `solution`（一轮一个字符串，提前结束的轮次末尾加 `|`），`ticks` 设为最短拍数再留 1 到 2 拍余量。
4. 运行 `npm test`。`tests/levels.test.ts` 会对每一层做两项检查：参考解在真实规则下能过关，且用的人数等于 `par`；人数少于 `par` 时求解器找不到任何解。
